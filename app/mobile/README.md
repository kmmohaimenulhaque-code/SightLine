# app/mobile

The phone application. **Not started** (Phase 6). The only code here is `android-probe/`: a measurement-only
Camera2 capability probe and OIS / gyroscope logger for experiment E-004b (compiled; not yet run on a device).

## Platform decision — PROPOSED, needs owner approval (ARCHITECTURE.md D-012)

**Android first, native (Kotlin or Java, Camera2).** Reason: measurement integrity depends on capabilities that the
Android Camera2 API exposes explicitly (VERIFIED in the Android reference, see `research/RESEARCH_LOG.md` R-006):

* turning EIS off (`CONTROL_VIDEO_STABILIZATION_MODE`) and OIS off where supported (`LENS_OPTICAL_STABILIZATION_MODE`);
* per-frame OIS shift samples (`STATISTICS_OIS_SAMPLES`, API 28+) to compensate when OIS cannot be disabled;
* timestamp base (`SENSOR_INFO_TIMESTAMP_SOURCE`) and rolling-shutter skew (`SENSOR_ROLLING_SHUTTER_SKEW`).

iOS second: per-frame intrinsics are available, video stabilisation defaults to off, but no public control for
disabling OIS was found (UNVERIFIED; CAL-EXP-1 decides which iPhones are usable).

Cross-platform UI frameworks (Flutter, React Native) do not remove the need for native camera modules, so they add
a layer without helping the measurement core.

## Shared measurement core

Port `app/vision`, `app/calibration` and `app/scoring` (the Python reference, D-001) to a portable library
(C++ or Kotlin Multiplatform — OPEN). The port must reproduce golden outputs generated by the Python reference on the
synthetic set within stated tolerances before it is trusted.
